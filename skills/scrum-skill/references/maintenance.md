# Evolve from real use

Keep a versioned, reviewed skill. The skill's generated workspace records its version;
consumers should pin a reviewed release when reproducibility matters. Updating this
repo does not silently update project instructions or already-installed plugins.

1. Describe an observed failure and the minimal useful correction.
2. Reproduce it with invented, project-neutral inputs. Keep raw project facts, logs,
   people, credentials and restricted reference documents out of this repo.
3. Add a behavioral regression expectation or isolated forward-test scenario.
4. Review for Scrum accuracy, user intent, cross-host behavior and authorization.
5. Run package/script validation and relevant scenario tests, update version/evidence,
   and publish through reviewed source changes.
6. Offer consumers a reviewable migration; preserve local customization and prior state.

Prefer a narrow correction over a growing pile of universal rules. A regulated
project's safeguard or chosen UI package is not automatically appropriate for every
project. Preserve the evidence that motivated a change in the originating project's
approved local records; only the generalized lesson belongs here.
