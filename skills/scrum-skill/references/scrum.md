# Scrum commitments and events

Use the Scrum Guide (November 2020) as the normative framework reference. The
Scrum Primer 2.0 supplies older supporting practices; use the 2020 accountabilities
and commitments where terminology differs. This package adds AI/project practices,
not new Scrum rules. Without the full framework, call the process Scrum-informed.

| Artifact | Commitment | Keep inspectable |
| --- | --- | --- |
| Product Backlog | Product Goal | Ordered work, user value, refinement and uncertainty |
| Sprint Backlog | Sprint Goal | Selected work plus Developers' real-time delivery plan |
| Increment | Definition of Done | Usable integrated outcome and quality evidence |

Sprints have fixed lengths of one month or less. A new Sprint follows the previous;
only the Product Owner can cancel one when its Goal becomes obsolete. Unfinished
work does not become Done because the timebox ended. Refinement is ongoing and
is not a separate required event or universal Definition of Ready.

| Event | Purpose | Guide maximum for one-month Sprint |
| --- | --- | --- |
| Sprint Planning | Why the outcome matters; what to select; how Developers plan delivery | 8 hours |
| Daily Scrum | Developers inspect Goal progress and adapt their next plan | 15 minutes each working day |
| Sprint Review | Team/stakeholders inspect outcomes and adapt what to do next | 4 hours |
| Sprint Retrospective | Improve quality/effectiveness based on the last Sprint | 3 hours |

Shorter Sprints usually use shorter planning/review/retro events. A two-week cadence
is an optional starting point, not a mandated Scrum duration. Async agent notes can
prepare an event; do not report an event occurred without actual participation.
Review is a working conversation, not merely a demo or approval gate. A usable
Increment may be delivered before Review if applicable release controls permit.

Acceptance criteria describe an item's behavior. DoD is the shared Increment quality
commitment, tailored to the product/organization. CI, reviews and safety requirements
apply when the project includes them; a non-software project needs its own evidence.
Do not silently waive an agreed quality criterion because infrastructure is missing.
Record the limitation and return unfinished work for reordering. Product/legal release
decisions cannot be inferred from a green check or a merge.
